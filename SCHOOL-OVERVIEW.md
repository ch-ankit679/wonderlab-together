# WonderLab Together — school overview (6.0)

**What it is:** a static, browser-based science learning platform with two guided chapter pathways with larger realistic visual scenes and audited diagram labels: **Cell: Structure and Functions** and **Materials Around Us**.

**Student experience:** each chapter contains six lessons written directly to students. Students read clear explanations, open vocabulary, connect ideas to everyday examples, hear Pip automatically narrate the lesson, question choices, lab observations and feedback where device speech is supported, and explore an animated model, complete a student mission and answer a concept check with feedback. After the lessons, teams take part in a separate 12-question Wonder League challenge.

**Multimedia:** 12 lesson-specific interactive labs cover cell organisation, cell structures, membrane transport, cell energy, plant/animal cell comparison, specialised cells, material sources, material properties, bridge loading, light transmission, dissolving and water displacement.

**Adult setup:** the adult launching the class selects the chapter, session time and team count; team names are optional. During the session, the adult mainly operates the shared screen and does not need to narrate the lesson. The lesson screens themselves are student-facing and do not contain teacher scripts or teacher-only instruction panels.

**Deployment:** static HTML, CSS and JavaScript on GitHub Pages or a local static server. No school server, database, student accounts, installation, AI API key or paid service is required for the core experience.

**Privacy and data:** the class shares one screen. Session data stays in browser memory until a team-level CSV is downloaded. The CSV does not require individual student names.

**Limitations:** separate student-device joining and synchronisation are not supported. Voice is browser/device text-to-speech; it does not recognise spoken answers. The adult still handles screen navigation and students select answers. Actual workload reduction requires pilot measurement. Animations and simulations are simplified educational models, not high-fidelity scientific instruments. Curriculum mapping is a reference, not board approval. The platform has not yet been validated in a school pilot; improved learning outcomes and reduced workload need to be demonstrated with classroom evidence.
